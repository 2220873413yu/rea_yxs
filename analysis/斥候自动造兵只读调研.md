# 斥候自动造兵只读调研（2026-11-06）

本次仅读取已有兵营缓存与原生Lua函数，未改动助手业务代码、未发起训练或使用加速道具。原始依据见 `evidence/scout-training-readonly.txt`。

## 已确认

- 原生 `SoldierTrainingNewDialog.setContentInfo` 的斥候分支对应兵种803；不是414。兵营响应rsp[4]也包含803。
- 803与411/412/413使用相同的兵营数据布局：a[3][1]可用量、a[3][2]编队量、a[3][3]当前训练剩余毫秒、a[3][4]训练队列数量；a[2]训练位容量、a[6]兵种数量上限、a[1]单次训练秒数。
- 只读快照：可用12、编队0、上限58、训练中2、训练位8、单次训练375秒（6分15秒）。快照时间晚于用户截图，训练完成会改变数量，截图显示11不构成矛盾。
- `getTrainLeftTimeCacheMap1():get_Item(803)`存在，快照包含2项；可以沿用按训练结束时间检查的机制，无需增加固定网络轮询。
- 原生 `sendTSLGTrainSoldierReq`接受兵种参数，不单独限制三大兵种，斥候使用同一训练入口。原生 `BarracksArmItem.trainAccelerateCallback`也从soldierID取得目标，没有排除803的分支，进入相同103类训练加速窗口。
- 升级中禁训是兵营公共判断，加入斥候后同样应执行。

## 实现涉及范围

目前界面、Python兵种注册、Lua白名单以及JS消费门禁均只支持411/412/413，不能只加一个界面复选框。需要统一加入803，显示顺序与游戏一致：弓兵、骑兵、步兵、斥候。

现有每兵种容量预算、训练位填充、训练到期检查与补满停止可复用；时长、上限和训练位均读取803自身的实时值。是否使用五分钟训练加速继续跟随现有独立勾选框，默认不使用。

斥候仅扩展可训练兵种，采集/打野的英雄默认编队与随从兵种校验仍按游戏原生方案，不因此允许携带斥候。
