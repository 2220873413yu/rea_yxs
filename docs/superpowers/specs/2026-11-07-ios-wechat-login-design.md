# iOS 微信扫码登录与账号数据重建

用户已确认按两次成功验证的原生 iOS 微信扫码流程加入助手；切换账号后重读数据，自动功能默认关闭。

## 接入方案

助手顶部提供「iOS 微信扫码登录」和「重新读取当前账号」，显示当前角色、等级与平台。推荐复用客户端 LoginCloudMatrix.onBtnIosWechatClicked；不修改安装包、不保存或替换 Token。独立登录脚本需要额外窗口，改包增加维护成本，均不采用。

登录前撤销全部自动操作权限，等待旧工作线程退出，关闭旧连接。若仍登录，调用一次原生退出回到登录页；协议由用户手动确认，助手不代为同意。每次点击只发起一次二维码，不重试认证请求；用户扫码授权。等待期间只检查本地登录状态，不定时请求服务器。

## 账号隔离

每次连接分配独立事件代次，旧线程、旧定时任务的消息不能更新新界面。清空旧兵营、英雄、属性、队伍、矿场、烽火台、收益与检查时间显示。保留已保存的资源坐标、英雄选择和事件类型选择，它们不会自动开启功能。

登录完成后读取服务器登录结果，显示角色与平台；等待用户进入西游幻境，主动查询兵营成功后初始化其他模块。原生响应、英雄与部队查询均来自新连接。初始化或账号变化失败时保持关闭，不发送自动操作。

绑定当前登录响应、模型实例及世界响应；每次桥接操作执行前校验仍是当前会话。发现退出、账号或地图变化即停止并重新等待、加载当前账号。只检查本地状态，不增加固定网络轮询。

新连接所有自动总开关关闭，道具勾选关闭。打野刷新定时开启在新会话暂停，用户本会话主动开启打野后恢复既有定时规则，避免换号后自动出征。

## 验证

覆盖协议未勾选不调用登录、单次二维码、取消与超时不重试、旧事件丢弃、旧线程未退出不连接、会话变化阻断操作、重新初始化和所有自动权限关闭。运行已有测试并启动助手检查布局与当前账号只读初始化；实际扫码由用户完成，不自动出征、领奖或消耗道具。

## 2026-11-09 身份缓存与拒绝处理修复

现场读取确认：SDK 已换成扫码授权账号，`TicketsProtocol.strOpenId` 仍可能缓存另一个账号。消息公共头读取该缓存，登录请求体却读取当前 SDK Token，因此不能仅凭微信授权成功就认为游戏身份一致。

账号管理和顶部 iOS 微信扫码入口统一使用账号服务。每次认证安装临时发送与响应校验，在原生登录请求即将发送时确认 SDK 授权成功、登录方式正确、请求 Token 与 SDK 相同，再清理 Apollo 和 TicketsProtocol 的本地身份缓存，重新确认 OpenID 与 Token 一致。仅转发一次原生登录请求，不改 Token、身份值或已保存票据，不新增网络轮询。

临时响应监听保留游戏原有处理。服务器返回任何明确非零登录码时，助手停止等待并关闭本次认证；客户端在等待期间重复发送登录包也会被阻止。成功、取消或失败结束时移除临时监听并恢复原发送函数。原票据仅在本次身份与服务器成功响应均确认后才更新；明确拒绝不保存、不标记其他账号失效。

本地回归复现了旧 OpenID 配新 Token，覆盖身份变化、Token 不一致、登录方式不一致、服务器拒绝、原生重复请求、取消清理和缓存成功假象。另在模拟器完成安装后立即清理的兼容性检查，未发送认证请求。真实扫码登录仍需用户手动验证。
