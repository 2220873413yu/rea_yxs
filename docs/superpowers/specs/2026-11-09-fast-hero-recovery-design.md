# 普通与快速英雄恢复

用户批准将单轮实测成功的快速恢复加入助手：选择普通或快速；快速每秒最多3次，不等待前次响应，后台核对响应、道具和冷却，完成停止用道具，结果不明不自动重试。

## 界面与共享规则

英雄恢复页增加“恢复模式：普通／快速”。启动和切换账号默认普通，自动功能仍默认关闭。模式在自动恢复、自动采集运行时锁定；后台也禁止修改正在执行批次的模式。自动恢复勾选名单和采集恢复需求仍通过同一个串行工作线程与授权集合处理，不另开恢复线程。

普通模式沿用逐个确认。快速模式一次选择一个符合条件的英雄，每批最多3个五分钟恢复道具；上限同时受当前库存与剩余冷却的完整五分钟份额限制，最后不足五分钟的余量在前批核对完成后单独使用一个。这样避免缓存尚未更新时，把自然流逝的尾部几毫秒误算成还需额外一张。每次原生发送后至少间隔334毫秒，连接级限速跨批次及英雄保留，避免滑动一秒内出现第4次请求。网络或调度慢时实际速度可低于每秒3次。

批内只等待限速时刻和本地桥调用完成，不等待前一次服务器响应。Lua在主线程重新检查身份、数据新鲜度、活动状态、剩余冷却和道具；已恢复则停止后续步骤。关闭开关撤销后续动作；已发送请求仍核对。

## 结果归属与停止

使用已有游戏网络日志的增量游标记录协议186的所有请求和响应，逐一检查英雄ID、业务类型3/500、恢复道具70291及数量1。不得用仅保存最后一条响应的原生缓存推断3次都成功。并发手动加速或其他类型响应视为归属不清，停止。

发完一批后，必须确认同数量成功响应，再主动获取新英雄和部队数据，核对库存减少数量及冷却缩短；完成本批核对才允许下一批，不固定轮询。响应缺失、服务器拒绝、桥超时、状态改变或核对不符均停止恢复及依赖恢复的采集。未知状态在连接与工作器中保留，普通／快速切换、重新开启或采集需求不得绕过；提示核对游戏并重新连接，不自动重发。

恢复完的英雄停止消费，主开关保留既有监控规则，仍只处理勾选英雄或采集明确需求；不恢复正在出战的英雄，不改打野、烽火台或联盟采集的选人规则。

## 验证

隔离测试覆盖冷却／库存限额、先发3次再读响应、跨批限速、关开关后核对已发请求、原生提前完成、失去资格、响应缺失、拒绝、外来响应、扣量／冷却不符与未知结果锁定，以及模式选择和账号切换。

556项现有及新增测试通过；整套Tk测试需在主线程禁用自动循环GC运行，避免测试对象在工作线程释放时触发Tcl错误。另用先前用户授权的骊姬单轮测试原始记录，离线回放新协议归属校验：3请求、3成功响应，无新增游戏请求。尚未用集成后的正式快速模式再次消费道具。
