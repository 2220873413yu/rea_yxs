# 西施自动恢复：已确认方案

在现有电脑助手加入一个默认关闭的固定开关“自动恢复西施”，目标英雄标识303。不开动态英雄列表，不改动原来的造兵开关；两项功能各自控制，共享连接并串行发送请求。

开启后持续监控西施。每次准备消耗道具前，刷新并核验英雄状态、恢复结束时间及恢复加速库存。只有明确确认未出战、未行军、未驻守、未采集、未参加其他活动，且确实处于恢复倒计时时，才允许加速。状态未知、查询失败、数据过期或无法判定时跳过并显示原因。实现采用状态0作为唯一允许状态，并排除两份活动部队集合中的西施；两份查询响应均须更新，且观察时间距当前服务器时间不超过三秒。

只使用五分钟英雄恢复加速70291，每次一个，收到响应并刷新状态后再决定下一次操作。剩余不足五分钟也使用一个完成恢复。不使用通用加速、训练加速或元宝。库存耗尽、请求报错或结果无法确认时停止自动恢复，避免盲目重发。

恢复完成后保持监控，等待之后的新一轮恢复；出战中只等待，不主动恢复或改变英雄行动。关闭开关后不再发送新请求，已经发出的请求不能撤回。重启助手后开关仍默认关闭。

频率调整（用户确认）：连续恢复期间，服务器成功响应、库存和进度核验完成后立即执行下一轮，不固定等待三秒，也不插入造兵循环的等待。仍逐个消耗、逐次刷新核验；出战或无需恢复时保持约三秒检查一次。连续恢复结束后继续处理造兵。

固定显示西施当前状态、剩余恢复时间、五分钟恢复道具库存和等待或停止原因。无需打开英雄楼界面。

验证：先用离线状态测试覆盖出战、未知状态、无冷却、无库存、关闭开关、响应不明及恢复完成场景；再读取真实状态核对。不会为了测试主动出征。实际消耗仅限用户主动开启此开关后的正常运行，不能把尚未验证的客户端调用路径描述为已通过服务器验证。

完成记录：新API在独立命名空间中完成真实只读查询，未覆盖旧助手API，未发送英雄加速。西施状态0、无恢复倒计时、活动部队中无匹配，判断等待；70291库存前后均为1574。实际服务器消耗路径仍待用户开启后验证。
