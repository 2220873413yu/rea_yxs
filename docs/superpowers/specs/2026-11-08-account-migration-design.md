# 多账号密码加密迁移

用户已确认：多选已保存账号，用密码加密导出，在另一台电脑解密导入，再使用目标电脑的本机加密保存。导入不自动登录，自动功能默认关闭，票据失效提示重新扫码。

## 交互和边界

- 账号管理列表支持 Ctrl / Shift 多选；导出1～50条可解密记录，最多64MiB明文数据。
- 导出选择 `.yxsaccounts` 文件，密码至少12个字符且需二次确认；导入选择文件并输入同一密码。密码不持久保存、不发布到日志或状态事件。
- 多选时禁止切换和删除，保持原先单账号操作的明确语义。
- 已存在同一身份的账号跳过，不覆盖新票据；身份按现有SDK账号、QQ/微信、安卓/iOS及区服的摘要区分，不按昵称区分。
- 已知失效记录保持「需要重新扫码」；其他导入记录标记「已保存，切换时验证」。导入不验证服务器登录，不恢复游戏SDK文件，不新增轮询。
- 导入和导出都先关闭自动功能、停止旧Worker。完成后不创建新Worker，不调用ADB或登录接口；手动重新读取或切换账号才重新连接。现有TicketExpired处理负责标记失效及提示扫码。

## 文件和加密

- 新增 `account_migration.py`，使用 `cryptography==50.0.2`。
- 固定格式：magic及版本1 + 16字节随机盐 + 12字节随机nonce + AES-GCM密文及16字节认证标签。头部整体作为AAD认证。
- scrypt参数固定为 N=131072、r=8、p=1，派生32字节密钥；导入文件不能指定任意耗资源的KDF参数。
- 明文是版本1的JSON账号列表，内容为已有受验证的账号档案；不打包助手偏好或自动功能状态。整个列表加密，文件头不泄露角色或账号名单。
- 不支持的版本、过大文件、密码错误或篡改均拒绝；全部账号先通过现有SQLite/平台/身份校验，才进入本机保存阶段。
- 导出仅把密文写入同目录临时文件，刷新后原子替换目标；失败或取消不覆盖旧文件。禁止写进本机账号库目录。
- 导入在账号操作互斥锁内检查重复，将所有新记录先以目标机器DPAPI加密、回读校验及密文暂存。再通过同卷硬链接发布新账号文件，禁止覆盖已有文件；发布异常回滚本批新增文件。临时目录只含密文。
- 明文仅在Python内存存在，不承诺运行时内存的可靠擦除。迁移文件排除Git。

## 验证

隔离测试使用假SDK票据和内存SQLite数据，不读取真实账号。覆盖两种不同本机密钥之间迁移、真实Windows DPAPI落盘、密码错误、盐/nonce/密文篡改、随机性、数量和大小边界、重复账号不覆盖、批次校验/加密/提交失败、取消、隐藏Tk多选及密码确认、迁移任务不连接游戏、不启动自动Worker。

物理电脑之间的SDK免扫码恢复需要用户在目标环境验证；能迁移档案不等于服务器一定接受旧票据。
