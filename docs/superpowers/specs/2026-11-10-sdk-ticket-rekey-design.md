# 单账号跨模拟器票据迁移

用户已批准先迁移“一条咸鱼”，原票据不覆盖，自动功能关闭，服务器拒绝停止且不重试。

旧雷电9 SDK只在内存解密微信数据库的access_token、refresh_token、pf、pf_key。
必须匹配原保存Token的SHA-256。当前Windows用户DPAPI封装单独迁移文件，秘密不输出、不明文落盘。
本次是同电脑迁移，不改现有密码迁移文件格式，不新增通用界面。

新版雷电14启动于暂停自动登录的登录页，SDK按目的设备密钥重加密四个字段，逐字段回读。
只改内存数据库副本并保存到独立迁移账号库；旧Windows账号库和旧模拟器数据库不改写。
目的模拟器原SDK数据库与偏好设置先DPAPI备份，再用现有停进程事务恢复。
沿用登录前身份校验与单次认证守卫；协议由用户本人勾选，确认同OpenID、平台、区服及服务器角色。
成功后的新票据只存独立迁移账号库，自动功能保持关闭。拒绝或结果不明均不重试，不声称票据可用。

验证：源Token哈希不一致拒绝；目的SDK回读不一致拒绝；原profile不变；真机新旧密钥重加密回读；一次登录及返回身份核对。

## 本次验证结果

- 旧雷电9四字段解密成功，Token与原保存校验值一致。
- 新雷电14四字段重新加密并独立解密回读一致。
- 使用独立迁移账号库提交一次登录，服务器确认“一条咸鱼”、50级、iOS微信，SDK身份及区服校验通过。
- 原账号DPAPI文件哈希不变。没有启动Worker或任何自动功能。
- 迁移数据与目的原SDK备份均仅以DPAPI密文保存在当前Windows用户的LOCALAPPDATA/REA_YXS/sdk-rekey-20261110目录。
- 新票据保存于该目录的destination-accounts独立库，本次没有替换默认账号库，也没有新增助手迁移按钮。
- 迁移及账号相关测试66项通过；Python编译与diff空白检查通过。
