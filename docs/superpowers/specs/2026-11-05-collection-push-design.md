# 采集状态推送唤醒与节流（用户已确认）

此处固定3秒兜底设计已被用户否决，由2026-11-05-collection-server-deadline-design.md取代；保留被动推送合并与1秒发现节流，取消周期兜底。

监听游戏原部队状态通知，仅读取本方部队更新，记录单调序号；回调不得查询、恢复或派兵。Python串行调度约每250毫秒读取本地序号，不访问服务器。新序号合并为一次待检查；空闲检查最短间隔1秒，无推送3秒兜底，不并发查询。正在查询时收到的新推送保留为下一次检查，不无限堆积。

检查先刷新服务器英雄及全部部队，再按原生队列规则判断是否有空位。队列满时不查兵营或逐点资源。撤回不暂停采集；返程中的英雄跳过，服务器确认空位及可用英雄后按清单与余量规则继续。状态推送仅作唤醒依据，不授权消费。恢复/出征成功后的必要响应确认维持现有速度，不受发现空闲的1秒节流影响。

关闭采集撤销待检查标记，停止本地标记轮询，原恢复与造兵开关独立。卸载清理新增部队观察者，部分注册失败回滚。推送遗漏或游戏没有传播该条通知时由3秒查询兜底。

离线验证：连续推送合并、最短间隔、查询期间新推送、关闭和重启、只认本方、观察者清理、满队列不查兵营、返程仍满不派、返城后续派。不得为测试额外撤回或派兵。
