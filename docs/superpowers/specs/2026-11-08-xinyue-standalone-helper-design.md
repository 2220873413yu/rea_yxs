# 心悦礼包助手：独立扫码、多账号保存与英雄杀签到

日期：2026-11-08

## 已确认的目标

新增独立 Windows 桌面程序。QQ、微信二维码直接显示在助手中，用户使用手机扫码并确认授权。整个扫码、取得登录上下文、查询、签到流程均不依赖模拟器、心悦 APP 或英雄杀客户端。

支持多个用户本人授权的账号。成功登录后本机加密保存完整请求登录上下文，后续选择账号即可查询英雄杀签到状态，并由用户点击签到。

现有英雄杀世界模式助手保持独立，本次不修改其界面和自动化行为。保留现有未提交的账号迁移等工作。

## 实现路线与已知边界

选择：独立对接官方扫码授权流程，在电脑程序内处理二维码、授权结果和凭据。查询、签到同样由电脑直接发送 HTTP 请求。

不采用：借助模拟器中的心悦官方 SDK 生成二维码并转显示到助手。该路线虽然更容易复用，但不满足用户明确要求的“扫码也完全独立”。

已验证的事实：

- 英雄杀在心悦服务中的游戏 ID 为 `1187`。
- 查询接口为 `POST https://bgw.xinyue.qq.com/xyapp.GiftSrv/GetGamesGifts`。
- 已验证的 Protobuf 查询参数为 `scene="signin"`、`gids=[1187]`。
- 一次经过明确授权的原生签到已成功；相应 HTTP 请求缓冲路径为 `/xyapp.GiftSrv/ReceiveGamesGift`，其消息定义只有 `scene` 字符串。
- 登录头包含 Token、OpenID、AppID、账号类型、Cookie、公共参数等；当前缓存中 Cookie 的 access_token 与请求头 Token 一致。
- 完整请求上下文已用 Windows DPAPI 加密保存；在心悦所有进程停止的条件下，从该文件独立查询成功，返回已签到 7 天。
- 本地客户端中存在 `LoginEngine.scanQQLogin`、`scanWXLogin`。QQ 原生入口使用强制扫码选项；微信入口先请求 `XySrv.UserSrv/WechatLoginScan`。这些静态事实不等于已经验证了脱离 APP 的完整扫码流程。

尚未验证、必须先解决的集成条件：

- QQ 和微信各自的独立二维码申请、授权状态检查、授权结果交换流程。
- 新登录账号如何生成查询所需的完整心悦上下文，而非借用旧账号的 Cookie 或公共参数。
- 独立签到请求是否还需要签到专用请求头，以及服务器签到状态枚举的准确映射。

先完成以上协议验证，再实现正式功能。某条官方授权链路若无法独立完成，应说明具体限制，不用模拟登录成功、旧账号上下文或模拟器回退冒充完成。

## 界面与操作

主窗口分为账号列表、扫码登录区、英雄杀签到详情、结果日志四部分。

账号列表显示备注或可验证的昵称、QQ/微信、英雄杀绑定角色、登录状态、最后确认时间。个人标识和凭据原值不进入列表或日志。用户可修改备注、删除选中本地记录，也可导入本机已经验证的加密上下文。

扫码区提供“QQ扫码”“微信扫码”、二维码、等待状态、有效期和“取消/刷新二维码”。二维码失效后由用户刷新。手机上的授权确认由用户本人完成。

签到区提供“查询签到状态”和“签到”按钮，显示服务器返回的签到天数、当前是否可领、绑定角色以及最近一次结果。第一版只处理当前选中账号的英雄杀七天签到，不增加批量、定时签到或其他礼包领取。

程序启动只加载本地账号记录，不主动请求网络。登录成功可做一次查询验证账号与绑定信息，随后保存；不自动签到。

## 扫码与登录上下文

QQ、微信使用各自独立的授权会话。每次扫码拥有独立的 Cookie 容器、状态参数、有效期和取消标识；新会话不得复用其他账号的 Token、OpenID 或认证 Cookie。

只在二维码等待授权期间，按官方协议需要检查授权状态。优先遵从服务端给出的间隔和有效期；若未返回，使用有上限的等待过程，不建立长期业务轮询。取消、超时、成功后均结束该授权会话；迟到的结果不得覆盖另一会话的账号。

得到凭据后，必须实际查询心悦服务器，确认该上下文可用，才能显示“登录成功”。昵称无法可靠取得时允许使用用户备注，不编造身份。

账号身份使用登录提供方和 OpenID 区分，同一账号再次扫码更新自己的记录。完整上下文包括已验证需要的请求头、Cookie、登录提供方、服务端返回的过期信息和查询所需配置。未知有效期明确显示未知，不自行假定永久有效。

使用 Windows 当前用户 DPAPI 加密整个敏感记录，加密后再原子写入 `%LOCALAPPDATA%\REA_YXS\xinyue_helper\`。不生成明文中间文件，不把 Token、Cookie、授权码或完整请求写进日志。取消或失败时不保存半成品凭据。

## 查询和签到规则

### 2026-11-08 原生领取确认核对

- QQ 独立授权已验证可用：OpenSDK 实际版本为 `3.5.17.lite`，需携带原生应用校验上下文；成功授权经 `imgcache.qq.com/open/connect/widget/mobile/login/proxy.htm` 和官方 `m_get_redirect_url` 还原回调。心悦 QQ 账号类型为 `qc`，不是 `qq`。
- 本次原生 APP 实际流程为：点击签到 → 友情提醒 → 确认礼包领取角色 → 勾选“30天内不需要再确认” → 最终确认 → 签到成功。此次只领到英雄杀宝具石碎片一项。
- 成功原生请求明确带 `t-gift-type: signin`；请求体长 8 字节，已提取的消息定义只有 `scene`，本次未恢复请求体逐字节内容。独立实现使用 `scene=signin` 并补齐该请求头；补齐后没有对已签到账号重复领取，真实独立领取仍需下一位未签到账号验证。
- APP 的 30 天确认是按账号保存的本地 `ignore_confirm_time` 时间记录。助手同样按账号保存本地确认，额外绑定当前角色资料摘要，30天到期或角色变化后重新确认，不调用任何绑定修改接口。
- 当前确认页默认勾选记住30天，用户可取消；首次点击“签到一次”需明确确认当前角色。未查到角色、状态未知或绑定受限则不领取。
- 每次领取前重新查询状态及角色；使用持久化尝试记录拦住双击、超时重试和重启后的重复请求。服务端结果不明时只允许只读查询，不自动重发。
- 原先 `10010` 失败时查询曾返回 `needUnbind/forceNeedUnbind=1`；APP 正常加载后两种登录上下文均变为0，原因尚未确定。不能声称仅添加一个头已证明解决10010，也不能据旧标记自动解绑。

当前可运行窗口优先实现 QQ 账号、查询和带角色确认的单次签到；微信仍未完成真实验证。批量签到是用户后续已提出的范围，当前窗口尚未提供该按钮，不把它描述为已完成。

### 2026-11-09 独立签到验证完成

用户扫码 QQ 账号 Spring，通过新版助手保存加密票据并查询为0天、状态0；在助手确认英雄杀 Spring / QQ大区角色，保留30天记忆，提交一次签到，业务成功1个、失败0个，随后只读核对为1天、状态5。本次未通过心悦APP领取，无重试。修正后的独立领取流程至此取得真实成功证据；状态5明确表示今日已签到，而非整个七天周期结束。上述“待另一个未签到账号验证”的历史边界已解除，早先10010的唯一成因仍未做隔离实验。

查询仅使用已经确认的 `GetGamesGifts` 接口和 Protobuf 参数。解析业务返回码、签到描述、领取状态及可用时间，不能只凭 HTTP 200 判断业务成功。

签到前先检查最新状态与绑定角色。判断“今日已签到”须依据已核实的服务器状态、领取时间和可领取时间，不能仅凭累计天数或电脑日期判断。状态枚举未核实或结果不明时禁用签到，并显示原因。

允许领取时，用户点击一次只提交一次签到请求。同一账号正在查询或签到时禁止并发操作，防止双击、切换选择或重复回调造成重复领取。操作开始后绑定选中的账号快照，不因列表选择改变而换用另一套凭据。

明确成功后可查询一次核对状态；请求超时、断线或结果不明确时，不自动重发领取请求，提示用户先查状态。登录态失效时提示重新扫码，不反复尝试签到。

不自动切换服务器绑定的英雄杀角色，不领取超级周礼包、活动礼包或其他游戏奖励，不购买、补签或消耗付费资源。

## 模块边界

- 界面：只接收公开的账号信息和任务结果，负责展示二维码与用户操作。
- QQ/微信授权模块：各自实现官方授权流程，向账号服务返回完整上下文；不负责签到。
- 账号存储：验证记录、DPAPI 加解密、原子保存与删除；对界面只返回公开字段。
- 心悦 API：编码 Protobuf、限定接口、解析业务状态；每次操作使用独立账号上下文。
- 任务协调：管理单账号串行操作、二维码取消、超时和结果归属；后台线程不得直接更新 Tk 控件。

现有研究脚本作为证据和实现参考。正式程序不依赖研究脚本里的进程号、堆地址、Frida、ADB 或原生函数注入。

## 验证与验收

1. QQ、微信均可在没有运行模拟器和心悦 APP 的条件下显示有效二维码，用户扫码后取得服务器认可的上下文。
2. 连续添加两个不同账号，确认查询结果与各自身份、绑定角色对应，取消或超时不会串号。
3. 加密文件能由新启动的助手进程读取并直接查询；验证期间不启动模拟器或心悦 APP。
4. 使用已签到账号验证显示及防重复逻辑，不发领取请求。首次真实独立签到选择用户本人授权、服务器确认尚未签到的账号，只发一次并核对结果。
5. 针对取消、过期二维码、重复回调、登录态失效、网络超时和签到结果不明做有意义的离线测试；不以反复真实领取作为测试手段。
6. 检查凭据不出现在日志、异常信息、UI 文本、版本库或明文临时文件中；原英雄杀助手不受影响。

本方案不承诺绕过服务端验证、无限延长 Token 有效期，或把其他游戏的扫码入口当成心悦登录入口。
