# 采集按服务器阶段时间检查（用户已确认）

取代此前3秒/60秒固定兜底方案：启用时确认服务器英雄和全量部队；读取每支采集部队当前状态及索引11的毫秒结束时间，使用同批游戏服务器时间转换为本地单调时钟的一次性定时器，阶段到点后查询确认并重排。仅使用服务器给出的时间，不用余量、采集速度、负重、资源等级40%/50%等公式推算。

采集开始/返程等本方状态推送作为合并唤醒提示，仍需重新查询服务器，不信推送直接派兵。被动标记本地250ms读取不发送网络请求；发现检查至少间隔1秒合并同批通知。恢复道具和出征响应确认保持现有速度。

阶段计时加1秒边界余量，不提前判断完成。到点仍为同一状态及同一截止时间，不无限重复查询该过期时间；等待新截止时间、推送或手动重新检查。无有效服务器时间时显示等待原因，不改用固定轮询。资源点暂不合格也不每30秒重查，30秒仅为已查询候选的临时避让缓存；下一次真实事件/手动检查才重查。

保留手动“立即检查”入口，用于无服务器阶段期限、资源补充或地图加载完成后的用户主动重查。只有自动采集开启时可用，不自行启用消费。关闭/重启复位定时及推送需求；实际出征成功后可补齐其他空闲队列。手动撤回不暂停；推送到达可提前检查，也接受错过通知时等原定时点。

验证：阶段时间顺序、服务器时钟与本机时钟差、不同等级相同服务器期限不受速率公式影响、已过期期限不自循环、无期限零轮询、推送/手动唤醒、停止复位、真实Lua时间字段读取、观察者完整清理与全量回归。仅模拟消费，不实际撤回、派兵或用道具。

实现与验证完成：91项Python/Lua测试和6组桥接门控测试通过。真实环境一次性只读加载并清理私有模块，collect_schedule返回两个state6部队原始end_ms和同批server_now_ms；未发游戏查询或消费请求。观察者计数15,4,9→16,5,10→15,4,9，原助手回调保持一致。实际Tkinter窗口需求837×878，适配当前1050×940及最小900×900；新增立即检查按钮的启用/禁用通过离线验证。需用户重启助手后生效，开关仍默认关闭。
