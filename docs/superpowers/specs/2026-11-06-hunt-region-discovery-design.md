# 打野区域发现与独立清单

按用户已确认的方案实现：不移动镜头，按设置的主城距离由近到远查询区域。使用显式24、18范围参数；查询和目标核实结束后重新加载原区域，避免把远处数据长期留在游戏的单槽缓存里。

区域计划由游戏原生距离函数计算。以40×30格核心矩形覆盖地图，每个核心中心的24、18查询覆盖其核心；相邻查询适当重叠。用中心距离减去核心覆盖半径得到保守的距离下界，按下界、中心距离排序。只计划可能与用户范围相交的区域；返回目标再按原生距离严格过滤。优先完成比候选目标更近的未扫描区域，避免直接跳到远处目标。

独立清单只保存本轮内存中的野怪ID、坐标、原生距离、配置、状态及最后发现时间；按ID去重，同坐标的新ID替换旧记录。缓存替换不删除记录；重新开启清空扫描进度和清单，账号／地图变化沿用现有中止保护。

每轮调度先确认服务器出征额度；满额或未知不发区域请求。有空位才逐个查询未扫描区域，每次只发一个区域查询并确认新响应。扫描完成后无目标则等待状态推送、阶段／冷却时间或手动检查，不固定重复扫描。立即检查可开始新的扫描轮次，但不清除本轮战力不足忽略坐标。

发现记录不授权出征。清单目标不在当前地图缓存时，先临时加载其区域，再查询目标详情和英雄，确认有视野、空闲、在范围内且胜券在握，使用游戏默认编队；提交后仍确认服务器回执。原有多队容量、英雄预留、战力不足本轮忽略、到达跳过及结果不明不重发规则保留。

停止开关后不继续查询新搜索区域，也不出征；正在进行的只读查询允许完成原区域恢复。网络失败、会话替换和响应归属异常明确停止，不把它当成空区域或继续自动重发。

区域请求复用打野代次门禁，关闭或重新开启会撤销尚未执行的新区域请求；恢复原区域属于只读清理，不受出征开关影响。查询期间用户若移动镜头，则恢复用户当前镜头附近的数据，不恢复已过时的旧区域。扫描耗尽后，实际部队阶段通知或额度减少可以触发新一轮有限扫描；单纯时间流逝不启动重扫。

验证：区域覆盖和边界、独立记录跨缓存保留和去重、近处优先、满额暂停和返城续查、扫描耗尽不轮询、停止／换图保护、查询与恢复响应代次、目标重新加载及最终视野／忙碌／战力校验。
