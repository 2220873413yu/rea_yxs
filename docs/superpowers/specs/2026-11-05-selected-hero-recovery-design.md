# 动态英雄名单恢复（用户已确认）

从游戏正常英雄和活动部队查询中获取名单、名称、战力、状态及恢复倒计时。启动及手动刷新时展示全部英雄，自动恢复时持续刷新；新增英雄默认不勾选。

用户手动勾选恢复对象，勾选结果以英雄标识保存在本机JSON文件中；启动时恢复勾选，但消耗总开关始终关闭。空名单不能开启。恢复期间锁定勾选，先关闭总开关再调整；刷新名单不覆盖勾选，不会把新英雄自动加入范围。名单中暂时缺失的已选英雄标记为不可用并跳过。

已选英雄轮流使用一个五分钟专用恢复道具70291，逐条确认响应目标、扣量和结束时间变化。服务器确认后立即继续下一位，无固定等待；所有已选英雄均无需恢复或忙碌时约三秒再检查。非普通状态、活动部队中匹配、状态未知或数据过期均跳过。错误和结果不明时关闭恢复，不自动重发。

沿用共享串行连接和独立恢复门控。桥接层允许列表与勾选一致，切换名单或关闭开关撤销上一轮排队请求。原造兵功能保持原规则。

验证包括名单与选择保存、名单变动、未选不可消耗、忙碌跳过、多英雄公平轮询、响应目标错配、快速关闭重开和连续恢复速度。真实环境只读验证名单，不为了开发测试消耗道具。

实现与验证：默认不勾选任何英雄，选择存入auto_infantry/hero_preferences.json；UI使用滚动表格并保留不可用的已选项。45项Python/Lua测试、5组桥接门控测试通过；真实只读取得47个英雄，恢复道具前后1548。服务器多英雄消耗尚未额外实测，首次用户开启后仍逐条确认并在异常时停止。
