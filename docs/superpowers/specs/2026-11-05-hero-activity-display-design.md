# 英雄状态维护与最后确认时间（用户已确认）

英雄表新增北京时间“最后确认”列。主状态结合服务器英雄状态和本方部队：采集state6显示采集中，state2及采集state3行军中，state9返城中，原生攻击/驻守/集结类型分别显示战斗、驻守、集结状态。特殊英雄状态20统一显示活动占用，不把当前模式名称硬编码成通用映射；未知行动/活动保留未知提示或状态码。

最后确认时间来自观察到的新服务器响应及本方部队推送，重复读取缓存不得更新时间。显示可保留上次已确认状态，配合时间列解释其时效；数据身份或部队信息不明时仍显示数据不明。恢复剩余0不代表空闲，终态推送只显示已返回待确认。

复用现有collection_runtime被动部队观察者，记录本方推送的显示状态。hero_view接口只比较已有英雄/部队响应引用与显示推送序号，变化时导出名单。Worker约250ms读取本地内存变化，不发送服务器请求，无新固定服务器轮询。未变化不发布UI事件；恢复/采集的fresh、busy、army_known、状态码判断保持原规则，显示推送不能授予消费资格。

验证：99项Python/Lua测试和6组桥接门控测试通过，覆盖多阶段及原生业务类型、特殊活动、旧缓存不冒充新确认、被动推送显示但不放宽恢复、无服务器查询的view接口、本地事件合并，以及现有造兵/连续恢复/采集回归。实际只读查询47英雄：陈圆圆/霍光采集中，褒姒/李世民/小乔活动占用，确认时间有效，连续相同view不发布变更。恢复道具1491→1491，脚本未发消费请求。

实际隐藏Tkinter验证状态/时间列显示、原英雄勾选保留、主窗口需求1029×939适配1050×940。代码需用户重启助手生效，三个开关仍默认关闭。未知英雄状态不做猜测，最后确认时间标记的是助手观察到响应/推送的游戏服务器时间，不冒充后台额外查询的时间。
