# 灵台试炼自动爬塔

用户已批准：默认关闭；无名单时按试炼可用名单战力选前三人；每层从已选三人中使用可用且服务器总战力最高者；达到原生时间或回合条件后仅跳过一次；胜利继续、战败立即关闭；不复活、不重试、不固定轮询服务器。

实现采用独立TrialService状态机、trial_runtime原生适配、桥接独立权限代次和TrialPanel。复用已实测选人、11006挑战、11015跳过与TPushPVEResult结算。协议响应成功不当作胜利，结算须匹配本场房间、牌桌及试炼模式。已有本轮名单沿用，不擅自结束本轮以重选。选人沿用原生每英雄小兵数量和库存约束；出战使用服务器TQCTHeroInfo总战力。

试炼切场会卸载地图，运行期间独占串行工作线程，关闭其他自动功能并取消打野定时开启权限；它们不自动恢复。账号身份校验持续有效，仅为已授权的试炼切场保留连接。关闭后立即撤销排队请求，已接受的战斗由用户处理；返回地图后重建普通世界会话，所有自动开关仍关闭。

只有开启、必要的阶段响应、胜利后返回和服务器允许的跳过时刻引发读取或行动。周期性本地状态读取只观察已接收数据，不发送服务器请求。每个请求先记录尝试，严格归属请求响应；任何不明结果关闭并禁止自动重发。失败保留结算供用户操作，不代点复活或重试。胜利按原生返回链进入下一层，不主动翻牌、分享或付费。

界面显示今日层数、历史纪录、剩余次数、三人名单/状态/总战力、阶段、跳过允许时间和最近结果。切号、重启、断线清空权限。测试覆盖失败停止、成功推进、取消代次、异步切场、陌生结果拒绝、未到跳过条件不发包、默认关闭与没有固定服务器轮询。

连续爬塔修正：原生派发可能保留安装监听前的方法引用，不能仅靠替换HallMsgMgr方法取得结算。状态读取同时查看PVEModel已经收到的结算，要求响应对象不同于挑战前快照，并匹配本场房间、牌桌、模式与队伍编号；不新增服务器查询。回归测试复现“模型已保存胜利，但方法监听未触发”后验证继续下一层，同时拒绝历史及其他队伍结算。

2026-11-07正式适配与TrialService连续两层实测通过：任务10020013（第4层）、10020014（第5层），队伍160450、160451，挑战与跳过各两次、返回两次，服务器均确认胜利。第二层胜利后关闭权限，未挑战第三次、复活、重试或分享。验证脚本analysis/verify_trial_continuity.py为明确授权的限两层实机诊断，不由助手入口调用；结果保存在本机analysis/evidence/trial-continuity-validation.json。
