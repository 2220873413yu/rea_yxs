# 弓兵、骑兵扩展设计

## 范围

沿用已实现的后台训练和指定道具加速链路。按用户最后确认的交互，使用一个“自动造兵”总开关，下面独立勾选步兵、弓兵、骑兵。步兵 ID 411、弓兵 412、骑兵 413，依据此前兵营响应与对应界面行的数量交叉核对。每种兵的实时上限从自身兵营数据读取，不固定写死54。

## 运行规则

- 总开关默认关闭，初始只勾选步兵；开启时至少选一种兵。多个兵种按轮询公平处理。
- 仍只有一个工作线程和一个游戏进程桥。每次只提交一个命令，确认该兵种的响应与状态变化后才进行下一次。
- 训练、加速、状态查询都明确携带目标兵种。运行期间锁定兵种选择，先关闭总开关再调整；关闭总开关立即禁止后续消耗请求，包括已排队但未执行的任务。
- 某兵种满额后跳过它，其他已勾选兵种继续；全部满额后关闭总开关，保留兵种勾选。
- 每种兵按开启时的实际差额建立独立消耗次数上限；道具库存共享，只用70251。余时浪费规则沿用已确认设置。
- 服务器响应中的兵种与本次目标不一致、超时、资源不足、道具不足、切换地图等异常停止所有消耗，避免错误重发。
- 原启动入口继续可用。更新时关闭旧窗口释放进程桥，新窗口总开关保持关闭，不自动恢复旧版运行状态。

## 验证

保留步兵已通过的边界测试，增加：三种兵公平轮询、满额兵种跳过、未勾选的兵种不训练、总开关关闭后停止全部、响应目标不符时停止、不同兵种具有不同上限时不串用。
对骑兵和弓兵各做一次有界的后台训练与加速验证，记录目标兵种、服务器响应、队列与道具扣量。
窗口实际显示三种兵的选择框和关闭的总开关后交付，明确尚未实测的部分。
