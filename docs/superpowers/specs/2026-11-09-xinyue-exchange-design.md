# 心悦英雄杀 G分手动兑换

用户已确认：先在原生 APP 各兑换一次粮木矿礼盒、元神宝盒，之后加入助手；仅点击时兑换，不自动执行，不重复提交。

## 原生验证

2026-11-09 秋风：起始2789 G分。粮木矿礼盒×10兑换一次后2699，扣90，周次数0/1→1/1。元神宝盒×5兑换一次后2549，扣150，日次数0/1→1/1。两次均出现原生兑换成功提示。最终服务器次数由助手只读查询核对。

请求均为 `xyapp.GiftSrv/ReceiveGift`，protobuf共136字节：gid=1187（tag1），scene=score（tag2），giftId分别1482、1481（tag3），role（tag4）118字节。无 t-gift-type，无 baseUin/num。第二次原生请求的role内容与实时GetPassCardV2英雄杀角色逐字节相同；未输出角色标识或登录票据。证据见 `analysis/evidence/xinyue-static/gscore-exchange-*`。

## 行为

- G分区域增加“兑换”标签页，显示所选账号余额、角色，以及两个礼包的数量、价格、次数、日/周限制和状态。
- 查询读 GScorePageNew 的 gscoreGift.giftGroups 内英雄杀条目和 GetPassCardV2 绑定；不查询其他活动。
- 点击具体礼包后，每次弹窗明确账号、角色、奖励数量与G分消耗。其他签到的30天角色记忆不能跳过兑换消耗确认。
- 提交前再查询，核对角色、礼包ID、数量、价格、周期及次数与确认快照一致，余额足够且服务器状态可兑时才发一次。
- 仅开放已验证类型11、receiveType0、module1，以及元神日限1、粮木矿周限1。配置变化时重新查询、重新确认；新类型未知状态不执行。
- 原样携带本次最新绑定的role；不写死或复用别的账号角色，不修改绑定。
- 按账号、礼包名称和北京时间日/周创建独占防重复记录，先落盘再提交。ID变化不能绕过已有记录。回执DPAPI加密。
- 收到响应后查询余额和次数，二者均符合预期才报告核对成功。不明或超时不重发，允许只读查询。
- 启动、切换账号仅展示本地缓存；不增加固定网络轮询。

## 验证

原生两次实兑换；助手只读核对余额和已兑换状态，不为测试再兑换。离线测试覆盖请求role、价格/数量/角色变化、余额不足、状态未知、次数用完、重复点击、超时后重启、跨账号隔离、响应成功但余额/次数未确认。
