# 烽火台四类事件自动化设计

2026-11-07：用户已确认按本方案实现四类分别勾选，宝藏允许正常消耗现有斥候、不购买，总开关默认关闭，动态读取额度，按服务器时间和推送检查，不增加固定轮询。既有救援规则继续有效。

## 方案选择

推荐沿用一个烽火台调度器，在界面使用“自动烽火台”总开关及救援、怪物、资源、宝藏四个类型勾选项。开启后只执行选中的类型，按类型分别运行原生流程，统一串行确认请求、队伍、英雄和奖励，便于复用现有停止门禁与服务器时间调度。

另一种方案是四个独立总开关，操作灵活，但启停和冲突处理更复杂；不推荐拆成四个独立工作线程，避免多个模块同时选择同一英雄或使用同一份过期队伍数据。

总开关每次启动默认关闭。首次迁移仅勾选原有救援；类型选择保存，用户可勾选新增类型。界面明确宝藏会消耗斥候。更改类型前关闭总开关，避免运行中的规划沿用旧选择。

## 四类执行规则

### 救援

沿用已验证规则：空闲且冷却结束的英雄，原生默认带兵，出征后确认到达才撤回；服务器确认可领奖才领取。事件完成不等于英雄返城，返城与冷却继续分开判断。

### 怪物

通过该烽火台事件配置读取敌方关卡与战力，使用游戏原生默认编队计算总战力及胜负提示。仅原生提示“胜券在握”且允许出征时选择英雄；满足条件中默认编队总战力最低者优先，同战力行军快者优先。英雄必须空闲、冷却结束。

出征前重新核对事件、视野、占用、英雄和原生额度。到达后在该事件对应的原生战斗流程允许时自动跳过战斗，并匹配结果；不把普通野怪的目标ID或跳过条件未经核对套用于烽火台。无正常跳过权限时暂不发起新的怪物出征，显示原因。只有服务器确认事件完成后才领奖。

没有合格英雄的事件在本轮排除；重新开启或收到新事件实例时重新判断。动作失败或结果未知不通过排除逻辑掩盖，不自动重发。

### 资源

查询该事件的实时资源详情、原生采集资格及可用英雄。按对应资源的有效采集速度排序，负重和行军时间作为后续比较条件；使用原生默认编队。若协议只提供事件统一资源指标，则使用原生指标，不猜资源类型。

正常行军并实际采集，按服务器阶段时间检查，确认完成后领奖。不到达即撤回，不套用普通资源清单的4万余量门槛或同盟共采位置策略。若一趟负重不足、英雄返回后事件仍可继续，重新查实时状态再决定下一趟；不得以本地估算的采集量宣告事件完成。

### 宝藏

走原生宝藏侦察流程，不选择英雄。按游戏配置和距离读取所需斥候，确认库存足够才提交一次侦察。勾选宝藏类型即允许按原生消耗使用斥候；不购买斥候，不消耗元宝，不主动启用造兵功能补充斥候。

侦察成功、事件完成、奖励入库分别确认。按服务器实际返回的完成条件继续，不把侦察成功直接视为可领奖。斥候不足时等待已有库存变化通知或手动检查，没有固定轮询。宝藏不占已核对的烽火台队伍计数，但仍遵守其自身侦察资格和库存限制。

## 共享规则与顺序

启动先只读核对服务器真实事件和本方行动。只有总开关开启且类型被勾选，才处理该类的新动作及已存在的进行中事件；仅为已勾选类型自动领奖。取消勾选的类型不再出征、撤回、跳过战斗、侦察或领奖。

优先处理已到达救援的撤回、已到达怪物的合法战斗操作、已完成事件的领奖，再分配新任务。新任务在已勾选且满足条件的类型间轮流选择，各类型内部优先近点，避免资源任务长期挤占全部新增机会。已接受的资源采集不为别的事件强制召回。

读取服务器返回的烽火台队伍上限，合并本方aim45行动和未被行动列表覆盖的处理中事件，去重计入手动及其他类型占用。返城状态9仍占额度，状态7不再计入；领奖移除事件不代表返城队伍释放。与普通采集、打野、联盟采集共用一个Worker串行执行；每次出征后确认本方行动再规划下一队。英雄占用同时检查本方行动和恢复冷却，本模块不主动请求使用恢复或加速道具。

使用服务器阶段结束、事件结束、刷新截止、英雄冷却截止及被动变化触发检查。刷新相对时长只在新响应到达时锚定；完成状态覆盖旧任务计时；过期且不变的阶段仅检查一次。没有有效时间则等待通知或手动检查，不增加固定网络轮询。

关总开关立即撤销该模块未执行的命令，不撤销服务器已接受的行动。每个有副作用的动作均先预留、只发送一次，并严格匹配请求和响应的事件/队伍/英雄；结果不明时停止该模块，不能以再次打开自动重发。其他模块门禁不受影响。

用户后续确认6395满额处理：只有严格匹配本次出征请求的6395拒绝，才清除对应未接受的本地预留，刷新一次真实事件/本方行动并进入等待，保持开关开启。发令前原生最终校验明确报告满额且未发送时，也进入相同等待，但不伪造服务器拒绝或释放动作预留。既有救援撤回、怪物战斗、完成领奖及宝藏不因英雄额度满而全部停滞。后续按服务器返城/阶段时间和被动变化检查；刷新确认此前队伍已释放且占用低于上限，才恢复新出征。没有可验证释放时维持等待，不固定轮询，不对6395文本、其他错误码、其他动作拒绝或结果未知放宽停止规则。
