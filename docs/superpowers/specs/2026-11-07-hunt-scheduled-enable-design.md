# 地图刷新时刻自动开启打野

用户确认：未勾选时，包括手动关闭和查询超时停止，到地图配置的刷新时刻自动开启；已勾选不重复启动。出征或跳过战斗结果不明仍保持停止。此规则补充此前“关闭打野清除本轮重扫待办”的规则：关闭只暂停当前运行，不取消下一刷新时刻的自动开启；关闭整个助手取消全部工作。

启动连接后，打野开关初始仍关闭；单独读取一次本地服务器时钟和地图sRefreshTime，换算为单次单调时钟截止时间。等待期间不新增服务器请求，也不固定反复读取本地游戏状态。到截止时间只读确认一次服务器时钟和配置，安排下一配置时刻。时钟尚未到点则按剩余时间重新安排；空配置不猜测刷新周期，午夜00/24去重，错过多个时刻合并为一次。

如果已经开启，定时器不改变现有开关、代次或队伍；原有刷新重扫逻辑照常处理。如果关闭，工作线程向UI提交带当前打野代次的开启请求；UI在主线程读取并校验当前面板范围，服务检查请求仍有效、连接存在、助手未关闭，之后才打开原有打野门禁并同步勾选。范围无效不启用；请求之后发生了新一轮手动开关、关闭窗口或断线则拒绝旧请求。

只读查询超时停止后，定时计划保留，下一配置时刻可以开启新检查；不会马上自动重试。出征未确认、跳过尝试未确认则拦截自动开启并显示原因，刷新时刻不能覆盖这些保护。连接／世界上下文变化或时钟读取错误暂停定时，不做固定重连轮询；用户显式开启或重启助手后重新校验。

定时开启后仍先查询本方队伍与实际目标，满队等待，不增加固定服务器轮询。原有视野、占用、默认编队、胜券在握、军队归属和不重发未知结果规则不变。开启仅授权打野，不开启造兵、采集、恢复或联盟采集。

界面明确显示手动取消只暂停至下一刷新时刻，并显示下一配置时刻或被阻止原因。日志记录hunt_auto_start_due、hunt_auto_start、hunt_auto_start_blocked和hunt_auto_start_failed，便于区分应触发、实际开启、保护阻止和范围校验失败。

验证：239项测试通过，包含真实只读查询超时捕获后在下一时刻恢复、手动关闭后开启、已开启不重启、只在截止时间读取时钟、未知出征／跳过阻止、旧代次／无连接／关闭窗口拒绝、时钟错误不重复查询、UI当前范围校验和勾选状态同步。未在真实账号开启自动打野或派兵，当前助手未重启；新逻辑重启后加载。
