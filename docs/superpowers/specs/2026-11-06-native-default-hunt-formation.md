# 自动打野改用游戏原生默认编队

用户在再次遇到6012后要求使用游戏默认编队，替代此前最少小兵策略。多队动态额度、视野/空闲/胜券在握筛选、逐队跳过以及本轮忽略规则保留。

第二次实际失败为2026-11-06 17:16:35，英雄110曹操、目标152695，左右各0名弓兵，返回6012。只读验证该目标为94,185，敌方50320；英雄基础战力132314，单兵21340，库存54，总上限2。原生默认编队为左右各1名，总战力174994，原生开始资格为true。模拟零库存时原生开始资格为false，即使提示胜券在握也不能出征。

实现通过协议槽位适配器运行原生SLGChooseHeroScene.updateSoldier，不创建真实UI、不开地图、不触发出征；UI显示回调只接收数据。位置调用原生SLGChosenSoldier.setPosition，数量来自原生默认过程，列表调用原生getSoldierInfoList，不再手工计算位置编号和最少数量。必须完整执行原生默认流程，校验开始资格、总数、库存、总上限和实际战力。

实际出征前重新生成默认编队，若计划数量/兵种已变化、开始资格为false或数量为0，则拒绝发送。直接复用默认士兵列表，不修改其位置和数量。用户后续确认英雄选择按“默认编队总战力升序、行军时间升序、英雄ID升序”排序，只在原生胜券在握且可用的候选中选择，不通过减兵降低总战力。理论满编只用于判断缺兵与本质战力不足，不修改真实库存。

验证：保留首次超额3名回归，新增第二次零名失败回归；默认满编、位置编号变化透传、原生开始禁止、零库存、编队与战力一致性、默认数量竞态以及既有多队调度均需通过。真实环境只读检查，未重发出征或消费道具。
