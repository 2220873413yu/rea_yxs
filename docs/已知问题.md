# 已知问题

## 玩家武将查询暂时无法获取全部装备和印方案

记录日期：2026-11-08。状态：待继续调研，本版本不宣称支持查询其他玩家的全部装备。

### 当前表现与影响

- 玩家详情、联盟成员查询和 Excel 导出只展示服务器公开返回的最强武将、最多三个展示武将，以及各自的一套佩戴资料。
- 暂时无法获取其他玩家同一武将的全部备用装备方案、全部印（宝具）方案，也不代表该玩家的完整装备库存。
- 当前展示的一套不能一概称为“第一套”；它是本次公开响应携带的佩戴资料。
- 本地缓存保存的仍是已成功取得的公开资料。清空缓存可以重新查询，但不能让接口额外返回未公开的方案。

### 已核对的证据与边界

1. 原生方案查询接口 1917 的请求包含武将组 ID 列表和 `iParam`，没有目标玩家用户 ID。原生调用来自自己的武将详情、配装页面。
2. 经用户授权只发送一次 1917 请求，使用对方公开资料中西施的武将组 ID `303`，`iParam=0`。服务器返回成功码 `0`，返回两套印、两套装备；内容与请求前当前登录账号的方案逐项一致，不匹配对方公开展示的佩戴资料。当前启用方案未改变。
3. 在已保存抓包及当前日志有界尾部中，审计到 81 个不同的成功玩家资料响应，共 324 条武将记录；每条最多 4 个印槽、6 个装备槽。40 次同一武将在最强与展示位置重复出现时，佩戴资料也一致。
4. 上述历史样本并非完整历史。用户提到早期曾取得两套资料，但目前尚未定位到能证明“同一名其他玩家、同一武将返回两套不同方案”的原始响应，不能据此断言服务器曾开放后又关闭该能力。
5. 1917 的一次验证只能确认该次返回当前账号的方案，不能证明其他原生入口均不支持查询更多公开资料。

### 后续方向

- 如找到早期两套资料的原始响应，核对当时登录账号、目标玩家、武将标识、接口和返回字段。
- 继续只读核对是否有其他带目标玩家身份的原生查询入口；在取得证据前不将当前账号方案当成对方方案展示。
- 确认其他方案能够正确归属目标玩家后，再考虑扩展缓存、界面与 Excel 格式。

本问题记录不授权新的服务器请求、装备或印方案切换；后续验证按用户具体指令执行。
