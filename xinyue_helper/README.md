# 心悦 QQ 签到助手

领取回执明细：抽奖支持直接GiftItem以及itemInfo内tag1列表两种实际返回，校验奖品名非空、数量大于0，不再生成“×0”。G分签到读取原生回执baseGscore/adBonusGscore/totalGscore字段，按实际返回记录本次获得4、5或其他分数，不用余额差冒充获分。每日礼包有实际回执奖品时直接显示；回执只有成功状态时，注明“礼包配置；回执仅确认成功”，不假称服务器返回了明细。

2026-11-09已从保存的加密回执修复12条本地记录，保留原开始和最后确认时间，修改前备份了SQLite。抽奖和G分离线恢复；旧每日记录缺少当时配置快照，按当前同ID固定礼包配置参考展示并明确标注来源。没有重复签到、领奖、抽奖，也未改动任何防重复记录。

一键签到：点击“一键签到（全部账号）”→等待预查→统一核对账号、角色及可领取项目→确认开始。串行处理G分普通签到、普通周礼包、赏金每日礼包和免费抽奖；已经领取、资格不足或有消耗的跳过。不会批量进行七天游戏签到、G分兑换、广告、激活、购买或改绑定。查询失败跳过该项；领取结果不明则停止该账号的剩余任务，继续其他账号，不重发。停止按钮只停止后续任务，已经提交的请求仍核对结果。

本地领取记录：“领取记录”按钮查看，保存于 `%LOCALAPPDATA%\REA_YXS\xinyue_helper\history.sqlite3`。包含北京时间、账号、角色、项目、成功/跳过/失败/待确认状态、实际奖品和结果说明。批量及单项手动领取共用记录。实际抽奖奖品未解析时写“实际奖品待核对”，不保存候选奖池冒充中奖结果。G分签到余额变化可点击记录查看详情。提交前先落盘，程序中断留下的记录下次启动标为待确认。只在本地保存，不含Token、Cookie或OpenID；旧历史不补造领取时间。打开、筛选和刷新记录不会发送网络请求。

G分手动兑换：选择账号 → “G分手动兑换”标签 → 查询兑换状态 → 点击粮木矿礼盒或元神宝盒 → 确认账号、角色、数量及消耗G分。点击才兑换，不随签到或查询执行。每次提交前重查，配置变化、次数用完、余额不足或角色变化时停止；超时不自动重发，防重复记录跨重启保留，回执本机加密保存。G分余额会同步到已经查询过的G分签到显示。

兑换原生验证：2026-11-09 秋风，粮木矿礼盒×10扣90分（2789→2699）、周次数0/1→1/1；元神宝盒×5扣150分（2699→2549）、日次数0/1→1/1。均仅原生点击一次，服务器状态已由助手独立查询核对。请求为 `ReceiveGift(gid=1187,scene=score,giftId,role)`，原生请求136字节；role与新查询的绑定角色逐字节一致，无t-gift-type、num或baseUin。助手没有再提交兑换测试，独立提交实现已通过离线测试；当前账号两个兑换按钮均不可再次使用。

G分普通签到：选账号 → 查询G分签到 → 普通签到一次。执行前再查服务器，今日已签到就跳过；未签到仅提交一次基础签到，不看广告、不抽奖、不兑换，不需要英雄杀角色确认。显示G分余额、今日状态及连续签到天数。超时或结果不明不重发，重启后保留防重复记录；可只读查询核对。

G分验证：2026-11-09 秋风通过原生“仅领基础奖励”签到一次，2885→2889（+4），连续0→1天，状态0→1。助手独立查询及已签到跳过路径已核对；独立提交的参数来自原生请求元数据与客户端反汇编重建，尚未用第二个未签到账号实测，不为测试重复签到。

双击工作区根目录的“启动心悦助手.vbs”，或在本目录的 Python 环境运行 `pythonw -m xinyue_helper.app`。依赖见本文件夹的 requirements.txt。

目前支持 QQ 独立扫码、多账号本机加密保存、查询英雄杀绑定角色与七天签到状态，以及带角色确认的单次签到。赏金任务区支持查询、领取每日礼包、免费抽奖一次。启动只加载本地记录，不主动查询。微信与一键批量签到尚未开放。

操作顺序：选择账号 → 查询签到状态 → 签到一次 → 确认领取角色。默认勾选“30天内不需要再确认”；按账号、角色记忆，到期或角色变化后重新确认。这里记忆的是助手本地确认，不修改服务器绑定。

每次签到使用最新服务器状态，带原生实际观察到的 `t-gift-type: signin`，只提交一次，随后只读核对。超时、失败或当天已有尝试时不自动重发；可以手动查询状态。不会解绑、重绑、购买、补签或领取其他活动。

赏金任务：选账号 → 查询赏金任务 → 领取每日礼包或抽奖一次。操作前重查角色、任务ID、次数及消耗；只允许零消耗，其他充值、会员和活动任务不处理。与签到共用30天角色确认，但使用独立的 `ReceiveGift` 接口和按礼包区分的防重复记录。任务状态1表示今日已领取，不能套用七天签到的状态5。候选奖池只用于展示可能奖励；结果使用服务器奖品，无法解析时明确提示待核对，绝不本地随机或再抽一次。

超级周礼包：选账号 → 查询周礼包 → 服务器确认可领取后点“领取周礼包一次”。不根据到了周一就领取；每次重新检查角色、资格、次数、消耗和配置。未激活、状态不明、费用变化、次数用尽时禁止提交，不会替用户激活、升级或重绑。与签到共用30天角色确认，按账号与北京时间自然周保存防重复记录；超时即使重启也不重发。因为领取接口是整组周礼包，仅在当前绑定游戏唯一为英雄杀时开放，避免意外处理其他游戏。

周礼包验证：2026-11-09 秋风实时查询为可领取、0/1、零消耗；独立提交一次 `ReceiveGamesGift(scene=weekGift)`，请求头 `t-gift-type: weekGift`，业务成功1个、失败0个，回执实际奖励资源礼盒×2，随后查询为状态1、次数1/1。没有重试、激活、升级或改绑定。

赏金验证：2026-11-09 秋风在原生APP领取每日礼包一次，获得酒馆刷新×1；随后通过独立客户端免费抽奖一次，服务端任务状态由0变1、次数由0/1变1/1。没有重试或修改绑定。本次抽奖的具体奖品未从当时回执解析出来，不能宣称已取得某个候选奖品；后续回执会本机加密保留，用于只读修正解析，避免为排查重复领取。

账号与确认记录使用 Windows 当前用户 DPAPI 整体加密，存放在 `%LOCALAPPDATA%\REA_YXS\xinyue_helper\accounts`。不要把账号文件加入 Git。另一个 Windows 用户或电脑不能直接解密这些记录。
