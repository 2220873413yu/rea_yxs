## 添加 QQ / 微信账号和绑定角色

历史绑定记录修正：此前已经服务器核对成功的 `verified` 记录不再永久阻止以后手动绑定。每次仍先校验当前票据、角色归属、服务器确实未绑定以及允许新增绑定，之后用户明确点击才创建下一次独立记录；保留旧记录及加密回执，不删除历史。任何一次结果未确认的记录仍阻止后续提交，已有当前绑定也不会重复提交。本次问题现场为旧记录 verified、当前服务器未绑定，新的点击被旧版防重逻辑提前拦住，并非本次服务器拒绝。

原生流程补充（2026-11-09）：进入游戏礼包的首次绑定页，点击英雄杀“绑定”前先请求 `CheckBind(gid=1187)`，再弹出区服与角色选择。助手已加入这项只读检查，区分登录票据失效与真正绑定受限。若出现网关 7001，提示“添加 / 更新账号”重新扫码并清除旧界面状态，不引导解绑；绑定操作还会在提交前重新确认资格，仅观察过的 result=0 允许继续，不猜测其他状态。无固定轮询。

现场对照：模拟器原生 APP 与助手保存记录的微信身份相同、Token 不同。旧 Token 的 GetPassCardV2 仍返回旧的 iOS 角色和 needUnbind=1，但 CheckBind 明确拒绝旧票据为 invalid credential / not latest；原生当前票据 CheckBind 成功、GetPassCardV2 返回未绑定且 needUnbind=0。因此不能只看旧 GetPassCardV2 标记就认定必须解绑重绑。重新在 APP 登录可能使助手保存的票据不再是最新，需在助手更新扫码。

模拟器原生角色选择器实际使用 android 平台；本次未确认该角色或开启通行证，避免把用户明确要求的 iOS 礼包绑定改到安卓。已取消原生选择，转为新版助手明确选择 iOS 微信后重新扫码验证。没有签到领奖；“开启通行证”最终按钮的独立网络请求尚未通过实际点击采样，不声称它有已验证的额外接口。

绑定受限的手动处理：选择账号 → “选择角色 / 绑定” → “检查 / 处理当前绑定受限”。先通过 CheckBind 校验当前票据，再只读展示服务器真实绑定的平台、区服和角色；不采用下方选择的其他平台或角色。未受限只查询，取消不解绑。受限时另行确认风险后，核对当前绑定与本账号角色列表，解除英雄杀礼包绑定一次，确认绑定已空，再把原角色原样绑定回去一次。最后同时核对角色一致与受限标记清除才报告处理成功。重绑失败可能暂时没有礼包绑定；任一步失败都停止，跨重启禁止重复处理，不签到、领奖或兑换。若服务器仍受限，会明确提示原生 APP 核对资格，不循环重绑。此路径已完成模拟服务测试，尚未在真实账号执行解绑重绑。

重启助手后点击“添加 / 更新账号”，先选择英雄杀的安卓或 iOS 平台，再选择 QQ 或微信；两项初始均为空，不按昵称推测。点击“继续扫码”，用对应本人账号扫描官方二维码。扫码独立进行，不依赖模拟器或心悦 APP。

授权后 Token 先在本机 DPAPI 加密保存，再打开“区服与角色绑定”。获取角色资料需要授权时会单独提示，选择同意后设置为“仅自己可见”。按你选定的平台获取区服，点击区服获取角色，角色列表不默认选中。区服列表有时返回“QQ大区”，而具体微信角色返回“微信大区”，界面分别显示列表标签和角色所属区服，不把前者当成角色实际区服。

区服显示修正：只有一个服务器区服时自动读取该区服角色，仍不默认选中任何角色。角色返回唯一一致的实际区服名称后，下拉框也改为这个名称（例如微信大区），保留原服务器区服 ID；不是按登录方式猜名字。多个区服仍由用户选择后读取；区服输入框已标注不是 QQ / 微信登录方式。用户“旅行”已用新微信票据成功只读核对 iOS 微信角色，不需要因此重新扫码。

点击角色 → “确认所选角色并绑定” → 核对账号、平台、角色 → 确认。提交前重查同账号角色，绑定请求只发一次，再读取服务器当前绑定核对。不自动解绑已有其他角色；遇到需解绑或受限状态时请在原生 APP 处理。超时或结果不明不自动重试，防重复记录跨重启保存；可手动“查询签到状态”只读核对。绑定的原始响应同样本机加密保存，不在界面显示 Token 或唯一角色标识。

添加账号、读取角色和绑定完成都不会自动签到、领奖、抽奖或兑换。已有账号可点击“选择角色 / 绑定”，重新明确选择平台后查询。后续签到、礼包和兑换仍由各按钮或确认过的一键签到触发。

验证：四种登录选择、必选空值、取消绑定、未选角色禁止提交、跨账号防串数据、平台校验、单次绑定请求、回读核对和未知结果防重均通过离线测试与 Tk 模拟流程检查；没有为验证界面而实际绑定或领取。新 RoleClient 使用已保存微信票据只读查到 iOS 微信“旅行”；真实绑定仍需用户在新版界面单独确认。
